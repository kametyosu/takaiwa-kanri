# 高岩工業 工事管理

案件・日報・見積・代理店回答・請求をひとつにつなぐ日本語の工事管理サイトです。React / TypeScript、Netlify Functions、Netlify Blobs を使います。Supabase や別サーバーは不要です。

## 機能

- 案件：得意先・現場、見積中／受注／完工／失注、契約金額、実績原価・粗利益・利益率グラフ、得意先別集計。
- 日報：社長40,000円・社員20,000円／人工（小数対応）。道路距離・燃費・燃料単価から燃料費を計算。エリア別駐車料金。各費用は概算／未取得／実費を区別し、根拠と作成時の計算条件を保存。
- 見積：品番・定型明細の再利用、数量・仕入単価・販売単価。代理店ごとに14日有効の専用URLを発行し、単価・送料・納期を比較、採用した価格を仕入単価へ取り込み。
- 請求：完工未請求の警告、複数の分割請求、部分入金、残額・支払期限の表示。過請求・過入金・重複請求番号をサーバーで拒否。
- 社内：管理者／社員ログイン、社員作成・停止、8時間セッション、JSON出力、直近1,000件の操作履歴。データは社内で共有し30秒ごとに再取得。
- 代理店：URLを知る対象代理店は依頼明細のみ閲覧・回答可能。社内の原価・販売価格・得意先・現場・他社回答は取得不可。回答後は再送信不可。URLは社内から無効化可能。

## 金額と計算

金額はすべて税込・日本円。人工費＝社長人工×40,000＋社員人工×20,000。燃料概算＝片道道路距離×片道／往復係数÷燃費×燃料単価（円単位四捨五入）。駐車料金は設定額／日。高速概算＝入力道路距離合計×設定単価＋固定額です。高速概算はIC・車種・割引を反映しない簡易モデルで、公式料金ではありません。ETC等の明細があれば実費と根拠に切り替えます。高速未利用は「実費0円・高速未利用」で記録してください。

住所からの距離取得は国土地理院の住所検索（候補の先頭）と OSRM の公開経路サービスを利用します。取得した地点・根拠を確認してください。高速回避・車種別ルート指定・公式高速料金の自動取得はありません。サービス停止・住所不一致の場合は、確認済みの道路距離を手入力してください。公開サービスに可用性保証はないため、大規模運用時は業務用経路APIへの切替を検討してください。住所をこれらのサービスへ送信します。

実績原価は日報の人工・燃料・高速・駐車・材料その他費用のみを合計します。見積の仕入額は計画値として表示し、二重計上しません。実際の仕入は日報に記録してください。概算・未取得や未計上費用がある間、利益は確定しません。利益率＝（契約金額−実績原価）÷契約金額。失注は売上0・発生原価のみを集計します。

## ローカル起動

Node.js 22.13以上。各クラウドタスクは分離済みなので、既存の `/workspace/takaiwa-kanri` を利用し、追加の worktree は作成しません。

```sh
npm ci --cache /tmp/takaiwa-npm
npm run dev:api
# 別ターミナル
npm run dev
```

ローカル検証専用ログインは `admin@example.test` / `local-test-password`。このAPIは127.0.0.1のみで動き、データはメモリ内で再起動すると消えます。これらの認証情報・メモリストアは本番には使用しません。

```sh
npm test
npm run build
npm run test:e2e
# Netlify公式ローカルエミュレーターで永続性を確認
XDG_CONFIG_HOME=/tmp/takaiwa-config npm run test:netlify
```

ブラウザテストはシステム Chromium を使用します。別環境では `CHROMIUM_PATH` で指定するか Playwright Chromium をインストールしてください。

## Netlify への初回公開

1. Netlify にログインし **Add new project → Import an existing project → GitHub** から `kametyosu/takaiwa-kanri` を選びます。GitHub 接続で当該リポジトリの読み取りを許可します。
2. 本番ブランチ `main`、ビルド `npm run build`、公開ディレクトリ `dist`。Functions の設定は `netlify.toml` にあります。
3. ローカルの安全な端末で `npm run password:hash` を実行し、12文字以上の管理者パスワードを入力します。画面には元のパスワードを表示しません。出力されたハッシュを次の設定に使います。
4. Netlify の **Project configuration → Environment variables** に以下を登録します。Functions の本番環境で使えるスコープを指定してください。

   | 名前                  | 内容                                       |
   | --------------------- | ------------------------------------------ |
   | `ADMIN_EMAIL`         | 管理者のメールアドレス                     |
   | `ADMIN_PASSWORD_HASH` | `npm run password:hash` で生成したハッシュ |

   ハッシュ・パスワード・NetlifyトークンはチャットやGitに貼らないでください。パスワード変更時は新しいハッシュを設定して再デプロイしてください。

5. デプロイします。Netlify Blobs は Functions の実行環境から自動接続されるため、独自のDB接続文字列やサービス鍵は不要です。Blobs が利用可能な Netlify プラン・プロジェクトで使用してください。料金上限と利用量はNetlifyで確認します。
6. 発行された HTTPS URL の `/api/health` が `{"ok":true,"configured":true}` を返すことを確認します。管理者でログインし、案件作成・再読み込み後の保持・別ブラウザでの共有を確認します。代理店URLを発行し、別ブラウザでの回答・社内への反映を確認します。

管理者設定がなければログインは503で拒否されます。公開時にデモアカウントを作成したり、匿名で社内データを開放したりしません。ブランチデプロイ・Deploy Preview は本番Blobsと分離される保証を設けていないため、この初版では本番用の環境変数をプレビューに配布せず、機密データをプレビューで扱わないでください。

### このクラウドから直接公開する場合

Netlifyのトークンは安全な環境設定で `NETLIFY_AUTH_TOKEN` として登録します（送信先 `api.netlify.com`）。チャットに値を送らないでください。既存サイトでは非秘密のサイトIDを `NETLIFY_SITE_ID` に指定します。GitHub接続による自動デプロイならトークンは不要です。

```sh
npm exec netlify -- deploy --build --prod --site "$NETLIFY_SITE_ID"
```

ネットワーク許可が必要な宛先は `api.netlify.com`、`app.netlify.com`、実際の `*.netlify.app` 公開先、必要に応じて `api.github.com`。住所取得の検証には `msearch.gsi.go.jp` と `router.project-osrm.org`。トークンをブラウザ用環境変数（VITE_等）に置かないでください。

## 保存とアクセス制御

Blobs ストア `takaiwa-management-v1` を強整合性で使用し、ETag の条件付き書き込みで同時更新時の上書きを防ぎます。業務データは1つのドキュメントでトランザクション化し、上限4MBです。小規模社内向けの初版で、超過時は保存を拒否します。大規模化する際はレコード単位の保存やDBへの移行が必要です。操作IDの直近500件は再送による二重登録を防ぎます。

パスワードは scrypt＋ランダムソルト。セッション・代理店URLは256bitの乱数で、保存する参照キーはSHA-256。セッションCookieは HttpOnly / SameSite=Strict / HTTPSではSecure。書き込みは同一OriginのJSONだけ許可します。ログインはメール・IP別で15分単位の試行制限があります。回答URLは秘密の権限そのものなので担当代理店だけに渡してください。URLの断片部分にトークンを入れ、Refererの送信も無効化しています。

社員は全案件を閲覧・編集できます。管理者だけが経費設定・アカウント作成停止・操作履歴取得を行えます。管理者のメール変更・パスワードハッシュ変更にはNetlify設定へのアクセスが必要です。メール認証、パスワード再発行メール、MFA、ファイル添付、PDF発行、請求取消、日報以外の過去データの編集削除はこの初版の対象外です。日報は編集から概算・未取得を実費へ更新できます。データを消さずに再デプロイでき、社内のJSON出力で定期バックアップを取れます。アプリからのバックアップ復元は未実装です。

## 検証範囲

`npm test` は計算・入力検証・分割請求・部分入金・認証・代理店分離・URL期限と無効化・並列更新を検証します。Playwright は実ブラウザで案件→日報→品番→定型明細→見積→代理店回答→仕入取込→完工未請求警告→請求→部分入金を操作し、モバイル幅も確認します。単体・ブラウザテストはローカルAPIのメモリストアで実行します。`test:netlify` は公式ローカルエミュレーターで Functions・認証・Blobsへの保存・エミュレーター再起動後の保持を確認します。SDK 11.1.9 のエミュレーターではGETにETagが付かないため、ローカル限定でデータ読込前に一覧のETagを取得し、条件付き書き込みを維持します。本番はGETのETagを使い、取得できない場合は安全のため保存を拒否します。Netlify上のBlobsの永続性と本番URLの確認は、実際のデプロイ後に別途行う必要があります。
